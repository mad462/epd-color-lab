# 3.7" 墨水屏 48 色 · 颜色方法论

> 这份文档记录**颜色是怎么测的、测出来偏在哪、怎么评估、最后采用了什么方法**，
> 以及**走过的弯路**。弯路那部分最值钱 —— 每个错误都有明确的症状和数据，
> 下次遇到类似现象可以直接对号入座，不用再摸索一遍。
>
> 文档里的数据表全部由 `host/palette_report.py` 生成，不是手抄的。
> 重新测量色板后重跑一遍脚本，表格就更新了。

## 一、背景

| 项 | 值 |
|---|---|
| 面板 | 3.7" JD7601 / GDEH037E01 级，720×480，6 色电子纸 |
| 驱动 | ESP32-S3 + ESP-IDF 5.4.1（`C:\FUCKEDA\e6-48color`） |
| 原生能力 | 硬件只有 6 色（黑/白/红/黄/蓝/绿） |
| 48 色怎么来的 | 时间域抖动 + 自定义波形。每个颜色用一组 799 字节的 LUT 波形控制，8bpp 索引 `= 高3位*8 + 低3位`，高 3 位走 plane0、低 3 位走 plane1 |
| 刷新 | ColorQual 3 相（约 14.6 秒）／ ColorFast 2 相（更快，颜色略差） |
| 方案来源 | FrameFilm（GPL-3.0），波形与 48 色索引编码取自该项目 |

**关键点：硬件是 6 色，48 色是"用时间换色阶"抖出来的。** 所以每个索引实际显示成
什么颜色，**只能靠测量**，标称值只是设计意图。

## 二、颜色是怎么测的

### 流程

1. 固件烧 `校准固件`，开机**直接进校准模式**，不刷屏、不挂载 TF 卡
2. 串口输入编号（1~52）→ 屏幕整屏刷出该编号对应的颜色
3. 用测量仪器读数
4. 把"编号 → 实测颜色"填进表格，导出 `docs/palette_qual_measured.csv`
5. 校准模式下按 `f` 可切到 ColorFast 2 相色板（57 个编号）

### 测量仪器（⚠️ 这里有个坑，见 7.1）

用的是一台 **LS173 分光测色仪**。规格：

| 项 | 值 |
|---|---|
| 照明方式 | **D/8，包含镜面反射光（SCI）** |
| 照明光源 | 全光谱 LED |
| 测量条件 | 光源 D65，视场 10° |
| 测量口径 | 8mm |
| 重复性 | ΔE\*ab 0.03 以内 |

**`SCI`（包含镜面反射光）不适合测电子纸** —— 它把表面那层保护膜的镜面反射
也算进读数，等于给每个颜色加了一份与颜色无关的白光。后果就是暗部被抬起、
色度被稀释。**详见 7.1 节。**

同系列里 `LS175 / LS172 / LS170 / LS171` 用的是 **`45/0` 几何**，
镜面反射从 45° 出去、进不到接收器，**天然排除镜面反射** —— 那才是合适的工具。

### 设计上的取舍（都是踩过坑才定的）

| 做法 | 原因 |
|---|---|
| 开机不刷屏，直接进校准模式 | 免得每次都白刷一遍屏 |
| **不自动刷**，必须串口输入才刷 | 用户要主动控制节奏 |
| 刷完清空串口输入缓冲 | 否则连按会排队，一次刷好几张 |
| 切换色板只切映射、不重排编号 | 否则和校准表对不上号 |
| 只输出三行：`开始刷编号N，原始索引I` / `刷新完成` / `输入N进入下一个` | 其它日志干扰读数 |
| 日志级别压到 WARN | 同上 |

### 数据文件

| 文件 | 内容 |
|---|---|
| `docs/palette_qual_measured.csv` | **实测原值，这是唯一事实来源** |
| `docs/palette_qual.csv` | 标称值（FrameFilm 的设计意图） |
| `docs/palette_fast.csv` | 2 相标称值（**尚未实测**） |
| `host/act/48-color-qual.act` | 实测值导出的 192 字节色板 |
| `main/palette_table.c` | 固件里的色板表，必须与 `.act` **逐字节一致** |

## 三、测出来的数据

### 3.1 明度范围与分布

实测最暗 **L\*30.9**（`#454951`），最亮 **L\*72.1**（`#ABB3AB`）。
**动态范围只有 41 个 L\* 单位**，而一张普通照片有 100 个。这是后面一切问题的总根源。

| L\* 区间 | 档位数 | |
|---|---:|---|
| 30~40 | 19 | `###################` |
| 40~50 | 15 | `###############` |
| 50~60 | 11 | `###########` |
| 60~70 | 6 | `######` |
| 70~80 | 1 | `#` **亮部档位太少** |

**档位严重偏向暗部。** 暗部有 19 个档位、亮部只有 7 个 —— 这个不对称直接导致了
后面的"暗区被压到一块"和"高光过曝"，见第五节。

### 3.2 结构性空洞：中间调没有中性色

L\*40~52 区间有 **18 个档位**，但其中 **chroma < 8 的一个都没有**：

```
L*40.6 #695E52 暖棕 b*+8.5    L*47.2 #4A7687 蓝
L*45.7 #487093 蓝             L*50.2 #567E86 蓝
L*45.9 #587451 橄榄绿         L*50.4 #697F4F 橄榄绿
L*46.2 #9C5D4E 红             L*51.6 #657E93 蓝
```

而 L\*40~52 恰恰是**肤色和大部分画面的主体所在**。后果：

```
中性灰 L*45 → 只能挑到 #695E52（b*+8.5，偏黄）
```

**这是"画面偏黄"的根源之一**，而且是色板的结构问题，不是参数能解决的。

### 3.3 实测色度只有标称的一半

| 索引 | 标称 | 实测 | 标称 C\* | 实测 C\* | 保留 |
|---:|---|---|---:|---:|---:|
| 3 | `#1F192B` | `#454951` | 13.6 | 5.3 | 39% |
| 8 | `#2E61BC` | `#487093` | 55.0 | 23.7 | 43% |
| 32 | `#67191E` | `#6A464A` | 38.9 | 16.6 | 43% |
| 39 | `#C42E21` | `#9C5D4E` | 72.6 | 31.0 | 43% |
| 55 | `#BCBB13` | `#91974A` | 74.5 | 41.7 | 56% |
| 59 | `#F0D307` | `#B4A543` | 84.4 | 51.7 | 61% |

**全部有效档位平均色度：标称 40.0 → 实测 19.5（保留 49%）。**

所有色族都这样，绿族尤其明显（标称 `#36673F` 这种绿 → 实测 `#587451` 橄榄色）。

**判断：这大概率是测量几何造成的系统性偏差**（漫反射/含镜面反射的测量方式会压色度），
而不是面板真的这么淡。但**我们暂时采用实测值**，因为它至少忠实反映了"上屏后眼睛看到什么"。

> ⚠️ **待办**：如果重测后色度明显回升，整张色板要重测。判断方法见第七节。

## 四、评估颜色的方法

### 4.1 试过的方法

| 方法 | 做法 | 结果 |
|---|---|---|
| **RGB 欧氏距离** | 网站原来的做法 | 和人眼感受差得远，早已弃用 |
| **CIELAB 加权欧氏** | `4·dL² + da² + db²`（明度 2 倍权重） | FrameFilm 的做法。**在标称色板上能用，在实测色板上会毁掉色相**（见下） |
| **ΔE2000** | 标准感知色差 | 更正确，但计算量大，且**绝对值指标会误导**（见 4.3） |
| **白点适应指标** | 把渲染结果按面板白点缩放后再比 | 得出了"白平衡最好"的结论，但**实际观感更差** —— 这是个陷阱 |
| **渲染出来亲眼看** | 用实测色板渲染量化结果，直接看图 | ✅ **最终起决定作用的方法** |

### 4.2 明度权重的坑（重要）

FrameFilm 用 `4·dL² + da² + db²`，即**明度占 2 倍权重**。这会让量化器
**几乎只看明暗、放弃色相**。在实测色板上后果很严重：

```
源肤色 #D6A082  (L*70.2 a*+16.2 b*+23.5)   健康红润
  权重 2.0 → 索引15 #ABB3AB (L*72.1 a* -4.3)   同明度的浅灰绿，红润全丢
  权重 1.2 → 索引47 #937670 (L*64.5 a*+10.3)   暖色保住 ✓
  权重 0.8 → 索引39 #9C5D4E (L*46.2 a*+24.1)   红润回来 ✓

中性灰 L*45:
  权重 2.0 → #695E52 (b*+8.5 偏黄)
  权重 1.2 → #585D57 (b*+2.8 基本中性) ✓
```

**结论：实测色板下默认用 1.2。** 这个数字是量出来的，不是拍的。

### 4.3 绝对值指标会误导（血的教训）

我用 `ΔE2000` 比较过三种色板，结论是"实测+白平衡最好"（适应后 ΔE 5.98 vs 16.69）。
**但上屏后这个方案明显偏暗。**

为什么：白平衡只按白点做通道增益（×1.49），**黑点没拉** ——
面板实测黑是 L\*31，增益后变成 46，中间调整体被压低。而 ΔE 是**平均值**，
它平摊了误差，**看不出来"整体被压暗"这种全局性错误**。

**教训：平均色差小 ≠ 观感好。全局性的明度偏移、色相旋转，在平均指标里会被稀释掉。**

### 4.4 最终采用的方法：渲染 + 亲眼看

```
1. 用**实测色板**渲染量化结果（不是用标称值渲染！）
   —— 标称值渲染出来的是"理想效果"，会骗人；
      实测值渲染出来的才是"上屏后眼睛看到什么"

2. 一次生成多个变体的对比图（网格 + 标签）

3. 直接看图判断，而不是看数字
```

工具：

| 脚本 | 作用 |
|---|---|
| `host/preview_variants.py` | 把管线拆成几段，逐段渲染，定位问题出在哪一步 |
| `host/sweep_params.py` | 扫明度权重等参数 |
| `host/sweep_blend.py` | 扫"实测↔标称"色板混合 |

**这个方法改变了整个排查效率。** 之前几轮我在猜机制、算指标，收效甚微；
改成渲染出来看之后，一轮就定位到了"面板映射导致偏黄"。

### 4.5 一个反直觉的具体案例

用户报"画面偏黄"。我先算平均色偏：

```
实测 w2 无映射:   dL* -4.8   da* -7.3   db* -1.5
```

**b\* 是 -1.5（偏蓝！），根本不黄。** 但 **a\* 掉了 7.3 —— 红色大幅丢失**。

红色丢了、黄色还在 → 暖色从"橙红"被读成"黄"。

**如果只看"是不是偏黄"这个描述去调 b\*，方向就完全错了。**
真实问题是**红润丢失**。这种"症状描述 ≠ 物理量"的情况，
只有渲染出来看 + 拆开 Lab 分量才能分清。

## 五、最终采用的管线

```
原图
 │
 ├─ ① 裁剪到 720×480 或 480×720
 │
 ├─ ② 自动色阶（可选，默认开）
 │     取亮度直方图 1%~99% 分位，映射到 [黑点, 247]
 │     · 上端只到 247 而不是 255 —— 留高光余量
 │
 ├─ ③ 暗部提升（默认 60）
 │     黑点抬到面板最暗附近
 │     面板最暗是 L*31，且 L*31 以下一个档位都没有；
 │     图像最暗若拉到 sRGB 8（≈L*2.6），暗部会全塌进最暗几档
 │
 ├─ ④ 阴影 / 高光（PS「阴影/高光」风格，**局部**）
 │     先求一张大半径模糊的亮度图当作"这一带有多亮"，再用它做蒙版：
 │       阴影蒙版 = (1-局部亮度)² × (1-该像素亮度)
 │       高光蒙版 = 局部亮度²     × 该像素亮度
 │     两者天然互不干扰。半径可调（越大越接近全局）。
 │
 │     ⚠️ 上一版是**全局曲线** `if (x > k)`，k = 255*(1-0.7*hs)。
 │        强度 100% 时 k 只有 76，中间调全被卷进去 ——
 │        实测症状："压高光的时候暗区也被压暗"。
 │
 ├─ ⑤ 饱和度 / 色偏微调（默认 0 / 0）
 │     在 Lab 里缩放 a,b（饱和度）+ 偏移 b*（去黄/加黄）
 │
 ├─ ⑥ 最近色匹配 + 误差扩散抖动
 │     度量：CIE Lab，明度权重 1.2
 │     抖动强度可调（默认 100）
 │
 └─ ⑦ 输出 8bpp 索引 BMP（调色板 = 实测值）
```

### 局部阴影/高光的实测效果

用一张"左半暗(40)、右半亮(215)"的测试图验证**互不干扰**：

| 操作 | 暗区 | 亮区 |
|---|---:|---:|
| 原始 | 40.0 | 215.0 |
| **高光 +100** | **39.8**（几乎不动） | 165.1（压下来） |
| **阴影 +100** | 58.4（提上来） | **216.8**（几乎不动） |
| 阴影+100 高光+100 | 58.2 | 166.9 |

**系数是调出来的，不是拍的**：`f = 1 + s·mShadow·0.9 − h·mHigh·0.45`。
一开始用 1.6，白区被乘到 0.04 —— 215 直接掉到 37，那是毁图不是压高光。

### 相机位："映射到面板范围" 默认关闭

这个选项把图像 L\* 压进面板的 `[31, 72]`。**实测对比后关闭了**：

| 设置 | 结果 |
|---|---|
| 映射 **ON** | 对比度被压平、亮部暖色被推到色板的黄色档位 → **发灰发黄** |
| 映射 **OFF** | 颜色明显更浓、对比更好 ✓ |

它的初衷（防高光死白）已经由 **④ 高光压缩** 更精准地解决了 ——
高光压缩只动亮部，不动中调和暗部的对比度。

### 各参数的推荐范围

| 参数 | 默认 | 症状 → 调法 |
|---|---|---|
| 自动色阶 | 开 | 画面平 → 开；过曝 → 关 |
| 黑点 | 60 | 暗部一团 → 75~80；发灰没劲 → 45~55 |
| **阴影** | 0 | 暗部看不清 → +30~+60（**只动暗部**） |
| **高光** | 0 | 高光死白 → +30~+70（**只动亮部**） |
| **半径** | 12 | 效果不均匀/有光晕 → 调大；只想动局部 → 调小 |
| 色偏微调 | 0 | 偏黄 → **-8 ~ -12** |
| 明度权重 | 1.2 | 色相偏 → 往 0.8 调；明暗分层 → 往 2.0 调 |
| 饱和度 | 0 | 肤色没血色 → +20 ~ +40 |
| 抖动强度 | 100 | 分层 → 130~150；太噪 → 80 |
| 映射到面板范围 | **关** | 一般不用开 |

## 六、走过的弯路

> 每个都记下来，包括**当时的错误结论**和**是什么数据把它推翻的**。

### ❌ 弯路 1：用 L\* 归一化去改色板

**做了什么**：把实测色板的 L\* 从 `[30.9, 72.1]` 线性拉到 `[0, 100]`，
色度按 `k = L2/L` 缩放。

**症状**：**暗部偏红**。

**原因**：暗色的 L 小 → `k → 0` → **色度被抹平**，所有暗色都变成"近似纯黑"。
量化器分不清暗部的蓝和红，随便挑 —— 挑到 `#6A464A`/`#504B56` 就是偏红/偏紫。

**推翻它的数据**：实测暗部本来就带色偏且方向不一
（`#454951` 偏蓝、`#6A464A` 偏红、`#504B56` 偏紫），归一化把它们抹成一样了。

**正确做法**：**改图像，不改色板**。色板保持实测原值（色度信息完整）。

> ⚠️ 注意区分：后来在**图像**上做压缩时，色度按 `L2/L` 缩放是**对的**
> （明度被抬升，比例在 0.5~1.6 之间，不会归零）。看着相似，对象和方向不同，后果相反。

### ❌ 弯路 2：只按白点做增益（"白平衡"）

**做了什么**：按实测白 `#ABB3AB` 做通道增益 ×1.49，把白拉成 255。

**症状**：**整体偏暗、对比度偏高、高光断层**。

**原因**：只拉白点、**黑点没拉**。面板黑 L\*31 被增益拉到 46，中间调整体被压低。

**推翻它的数据**：ΔE2000 说这个方案最好（适应后 5.98），但上屏明显更差
—— **平均色差掩盖了全局明度偏移**。

### ❌ 弯路 3：把"映射到面板范围"当成解决办法

**做了什么**：把图像 L\* 压进 `[31, 72]`。

**症状**：**发灰 + 偏黄**。

**原因**：
- 压缩 L\* 把对比度压平了
- 亮部暖色被推到色板 L\*60~67 那一段的**黄色档位**（那段只有 `#B4A543` `#A29847` 两个黄）

**推翻它的数据**：同条件渲染对比 —— 开映射惨白发橙，关映射颜色明显更浓。

### ❌ 弯路 4：跟着"偏黄"这个描述去调 b\*

**做了什么**：以为 b\* 偏正，去调色相。

**症状**：调了没用。

**原因**：平均 b\* 实际是 **-1.5（偏蓝）**，真正的问题是 **a\* 掉了 7.3（红润丢失）**。

**教训**：**症状描述 ≠ 物理量。** 用户说"偏黄"，物理上可能是"红色丢了"。
必须拆开 Lab 分量 + 渲染出来看。

### ❌ 弯路 5：用全局曲线压高光，把暗部一起压暗了

**做了什么**：一条全局曲线 `if (x > k) 压缩`，`k = 255*(1-0.7*hs)`。

**症状**：用户原话 —— **"我去压高光的时候，会把暗区也压暗掉"**。

**原因**：`hs = 100%` 时拐点 `k` 只有 **76**，那已经不是"高光"了，
**中间调甚至偏暗的中间调全被卷进去**。

**根本问题**：全局曲线没法区分"这个像素暗是因为它在阴影里"还是"它本来就是个暗色物体"。

**正确做法**：**局部**算法 —— 参考 Photoshop 的「阴影/高光」。
先求一张大半径模糊的亮度图当作"这一带有多亮"，再用它做蒙版：

```
阴影蒙版 = (1 - 局部亮度)² × (1 - 该像素亮度)     // 只作用在"暗的地方的暗像素"
高光蒙版 = 局部亮度²       × 该像素亮度            // 只作用在"亮的地方的亮像素"
```

**推翻它的数据**：合成一张"左半暗 40 / 右半亮 215"的图验证 ——

| 操作 | 暗区 | 亮区 |
|---|---:|---:|
| 原始 | 40.0 | 215.0 |
| 高光 +100 | **39.8**（几乎不动） | 165.1 |
| 阴影 +100 | 58.4 | **216.8**（几乎不动） |

**顺带的教训**：系数也不能拍。第一版用 1.6，白区被乘到 0.04 ——
215 直接掉到 37，**那是毁图不是压高光**。最终用 `1 + s·mS·0.9 − h·mH·0.45`。

### ❌ 弯路 6（工程，非颜色）：stdin 的 CR→LF 转换

**症状**：上传图片 CRC 对不上，**而且两次结果一模一样**（说明不是随机噪声）。

**定位过程**：用递增大小的测试文件 → 发现固件收到的长度比发的少 768 字节。
`200000 = 0x00030D40`，`199232 = 0x00030A40` —— **差的就是 `0x0D` → `0x0A`**。

**原因**：ESP-IDF 默认 `CONFIG_NEWLIB_STDIN_LINE_ENDING_CR`，
**把 stdin 里每一个 `0x0D` 都换成 `0x0A`**，二进制走 stdin 全被改坏。

**为什么潜伏了一整轮**：查了之前成功推送的文件 —— **它们碰巧一个 `0x0D` 都没有**。

**修复**：`CONFIG_NEWLIB_STDIN_LINE_ENDING_LF`（IDF 文档明确写 "no modification is applied,
input is sent to stdin as is"）。

### ❌ 弯路 7（工程）：打开串口会复位板子

**症状**：点"存到 TF 卡并显示"**刷到一半就挂了**；"只显示"不会。

**原因**：打开 CH343 会让 DTR/RTS 跳一下 → ESP32 复位。
"只显示"那条路等服务端等到 `显示完成` 才返回；
而"存卡并显示"我在改重试逻辑时**把 `显示完成` 从等待条件里删掉了** →
服务器存完就返回 → 网页 3 秒后自动刷新列表 → 打开串口 → **复位板子 → 打断正在进行的刷新**。

**修复**：存完之后**继续等刷完再返回**。

**衍生教训**：**任何一次串口打开都会复位板子**，所以"操作完成后立刻发下一个请求"是危险模式。

### ❌ 弯路 8（前端）：删了元素但没删引用

**症状**：两个发送按钮一直按不了。

**原因**：加说明文字时删掉了 `<div id="mapInfo">`，但 `render()` 还在往它写 `textContent`
→ 抛异常 → 后面的 `state.idx = sendIdx` 执行不到 → 按钮永远禁用。

**修复**：恢复元素，并做了常驻检查 `host/check_page.py`
（交叉核对 JS 引用的 id 和 HTML 里的 id，并单列 `render()` 会写到的元素）。

## 七、下一步建议

### 7.1 测量方式有系统性偏差 —— 已由仪器规格确认

#### 结论先说

**测量仪器用的是 D/8 SCI 几何（包含镜面反射光），对电子纸是错的测量方式。**

这解释了实测色板的全部异常特征：所有色族都比标称淡、平均色度只有标称的 **49%**
（40.0 → 19.5）、最暗只到 L\*31。

#### 证据一：仪器规格（**非循环论证**）

仪器是 **LS173** 分光测色仪，规格表里：

| 型号 | 照明方式 |
|---|---|
| LS175 / LS172 / LS170 / LS171 | `45/0`（45°环形照明，0°接收） |
| **LS173** | **`D/8`，包含镜面反射光（SCI）** |

- **SCI = 镜面反射光也算进读数**
- 电子纸表面有保护膜，会镜面反射一部分光，**这部分和底下的颜色无关** ——
  等于给每个读数都**加了一份白光**
- 后果：暗部被抬起、色度被稀释、对比度被压缩 —— **三者同时发生**

同一张表里 LS173 的「适用材料」写的是**塑料、油漆涂料、金属制品、陶瓷**
（通用工业、以漫反射为主），**LS175/LS172 才是「普通印刷品包装材料」**。
**LS173 不是给显示屏用的。**

#### 证据二：数据拟合 + 物理边界定出量级

用「杂散项混入」模型（`实测_线性 = a·真实_线性 + b`）对现有数据做线性拟合：

```
实测_线性 = 0.429 · 标称_线性 + 0.073
残差 RMS = 0.0244        （0~1 线性反射率尺度，很小）
```

**⚠️ 但这个拟合值 b = 7.3% 不能用 —— 它偏大了。** 两个原因：

1. 拟合拿**标称值**当「真实」，而标称本身是理想化的（尤其标称的黑 `#1F192B`）
2. **纯加法模型有硬约束**：减掉 b 之后的黑不能是负数

验证一下就知道：

```
实测最暗 #454951 的线性反射率 = 0.0695
拟合出的镜面项 b             = 0.0730
相减得"真实黑"               = -0.0035   ← 负数，物理上不存在
```

**改用物理边界定 b。** 面板对比度是已知量级 —— 参考同规格六色电子纸
（3.56″ DEPG0356 规格书：白反射率 30~34%，**对比度 15~22**）：

```
实测白 0.4218 / 实测黑 0.0695  →  实测对比度只有 6.1 : 1
```

6:1 明显低于 15~22 —— 正是镜面项垫高了黑。反推：

| 假设真实对比度 | 推出的镜面项 b |
|---:|---:|
| 10:1 | 3.0% |
| **15:1** | **4.4%** |
| **20:1** | **5.1%** |
| **22:1** | **5.3%** |
| 30:1 | 5.7% |

**采用 b = 5.1%**（按真实对比度 20:1）。由此修正：

| | 实测 | 修正后 | 标称 |
|---|---|---|---|
| **对比度** | 6.1 : 1 | **19.7 : 1** ✓ | — |
| 平均色度 | 19.6 | **26.9** | 40.0 |
| 明度范围 | 30.9 ~ 72.1 | **13.0 ~ 68.7** | — |

**修正后的对比度 19.7:1 正好落在同类面板的规格区间** —— 这是物理自洽的强证据。

（早先用拟合影像做的第一版「去污染」把对比度拉到 **114:1**、黑变成负数，
那是**过度修正**，已废弃。现在文件里的是物理边界版。）

**我们之前调的黑点 60、高光压缩、色偏微调……有一部分是在补这个镜面项。**

#### 修法（按优先级）

**① 先查 LS173 菜单里有没有 SCI/SCE 切换** ⭐ 最省事

这类分光仪很多支持切换。**有的话切到 SCE（排除镜面反射）重测即可。**

**② 没有就换 45/0 几何的型号**

`45/0` 下镜面反射从 45° 出去了、**进不到 0° 接收器**，天然排除镜面反射。
可用 LS175 / LS172 / LS170 / LS171。

**③ 测量细节（无论哪台）**

- **仪器贴紧屏幕**，8mm 口径要**完全落在显示区内**，别压到边框
- **关灯或遮光** —— 环境光是同一类污染源
- 预热 + 白板校准后再测
- 同一色测 3 次取平均（规格：重复性 ΔE\*ab 0.03 以内，很稳）

#### 第三方独立实测色板的交叉验证（关键证据）

[epdoptimize](https://github.com/paperlesspaper/epdoptimize) 提供了 **4 套独立测量的
Spectra 6 色板**（不同的人、不同的仪器、不同的面板批次）。拿它们的 6 个基色对照我们：

| 基色 | 我们实测 | spectra6 | aitjcize | spectra6legacy | boeber | 各参照 L\* 极差 |
|---|---|---|---|---|---|---|
| 黑 | `#454951` L\*30.9 | `#1F2226` | `#020202` | `#191E21` | `#1F2226` | 13 |
| 白 | `#ABB3AB` L\*72.1 | `#B9C7C9` | `#BEC8C8` | `#E8E8E8` | `#D6D6D6` | 13 |
| 蓝 | `#436183` | `#233F8E` | `#05409E` | `#2157BA` | `#416CE1` | 20 |
| 绿 | `#70834F` | `#35563A` | `#27663C` | `#125F20` | `#067406` | 9 |
| 红 | `#9C5D4E` | `#62201E` | `#871300` | `#B21318` | `#EA4843` | 32 |
| 黄 | `#B4A543` | `#C1BB1E` | `#CDCA00` | `#EFDE44` | `#DBD529` | 13 |

**方向完全一致**：四套参照全都比我们**黑得多、白得多** —— 即**我们的测量被压缩了** ✓
这从第三方独立来源再次印证了镜面项的判断。

**但不能用来精确定标。** 以下几点必须说清楚：

1. **参照之间分歧太大**：红色的 L\* 从 23 到 55（极差 32），
   比我们要测的偏差还大。用全部 6 色拟合，拟合出来的其实是"参照之间的分歧"，
   结果是荒谬的（b 变负数、对比度反而降到 3:1）。
2. **只用黑白两端拟合会过度外推**：得到 `真值 = 1.69·实测 − 0.101`，
   推出**白反射率 61%** —— 电子纸不可能（纸才 80%，电子纸白通常 30~40%），
   对比度也会拉到 **37:1**，远超同类面板规格的 15~22。
3. **原因**：他们的面板确实比我们这块强（不同型号/代次），拿它们当真值会
   把我们的数据**拉伸过头**。

**结论：物理边界校正（b=5.1%）仍是最佳估计。** 它同时满足两个独立约束：

| 约束 | 物理边界校正 | 锚点拟合 |
|---|---|---|
| 对比度落在同类面板规格 15~22 | **19.7 : 1** ✓ | 37 : 1 ✗ |
| 白反射率落在电子纸常见 30~40% | **37%** ✓ | 61% ✗ |

复现脚本：`host/check_measurement_bias.py`（物理边界）、
`host/calibrate_from_anchors.py`（锚点交叉验证）

#### 决定性实验（仍然建议做，5 分钟）

即使知道了仪器几何，做一遍能**定量**确认杂散项大小：

1. 面板全屏刷**最暗**编号（3）
2. 正常灯光下测 → 记 L1
3. **关掉所有灯**（仪器周围别漏光），同位置再测 → 记 L2
4. **若 L2 明显小于 L1 → 环境光也在贡献**（镜面项之外的第二重污染）

白色（编号 15）同样做一遍。再顺手：测**仪器自带白板**（应≈100）、
测**一张白纸**（通常 L\*93~97）。

#### 离线预判：去污染色板确实更好看

`host/compare_palettes.py` 的对比**不循环论证** —— 两个色板各自量化，但**都用实测色渲染**
（因为不管挑哪个索引，面板显示的都是实测色）：

| 变体（都用实测色渲染） | 观感 |
|---|---|
| 实测色板 黑点60 | 惨白、发灰绿、头发是灰的、天空没颜色 |
| **去污染 黑点25** | **明显更浓、头发是棕黑的、天空有暖色、皮肤有血色** |

头发那处最能说明问题：原始发色是**暖褐**，去污染版挑到暖暗色（`#6A464A` 类），
实测版挑到中性冷灰（`#454951`）—— 因为镜面项把暗部的色相差异抹平了。

#### 两条路

- **路线 A（推荐）**：用 SCE 或 45/0 几何**重测**。半小时测完 52 个色，
  之后所有参数都不用再跟测量误差搏斗。
- **路线 B（临时）**：先用去污染色板，但**黑点要跟着往下调**（60 → 20~30），
  因为这一版的黑是真的黑。

### 7.2 2 相色板的实测

`palette_fast.csv` 目前还是标称值。2 相用**完全不同的波形**，颜色和 3 相不是一套值。
校准模式按 `f` 可切到 2 相（57 个编号），约 15 分钟能测完。

### 7.3 排除色板里的"坏档位"

暗部那几个偏红/偏紫的索引（`#6A464A` `#504B56`）在特定场景会带来色偏。
实测数据在手，必要时可以把它们从可选槽里排除。
