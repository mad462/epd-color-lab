# 3.7″ JD7601 跑通 48 色 —— 实测记录

> 日期：2026-10-14
> 工程：``
> 屏：**兴泰 EPD037A02**（3.7″ / 720×480 / 六色 / JD7601）
> 波形来源：FrameFilm（GPL-3.0）`hal_epd_370.c` 的 9 张 799 字节波形表

## 结果

**48 色色板成功刷出。** 64 个索引各一块，ColorQual 3 相刷新，画面正常。

## 实际时序

| 步骤 | 内容 | 耗时 |
|---|---|---:|
| 0 | `full_clear` 波形 + 全 0 帧 | **2515 ms** |
| 1 | `qual_phase1` + 高 3bit 平面 | **5587 ms** |
| 2 | `qual_phase2`（复用控制器 RAM，**不重传图**） | **6444 ms** |
| 3 | `qual_phase3` + 低 3bit 平面 | **121 ms** |
| | **合计** | **≈ 14.6 s** |

> **比这块屏原来的六色全刷（实测 29.5 s）还快一倍**，而且颜色从 6 种变成 46/55 种。
> 自定义波形的效率远高于出厂波形。

## 关键协议（之前全猜错了）

```c
// 写波形表
EPD_W21_WriteCMD(0x00);          // ← 波形载入前导，之前没写

```

### 初始化

```c
// 复位：双脉冲
RST=0 20ms; RST=1 10ms; RST=0 20ms; RST=1 10ms;
wait_busy;
0xE9 0x01;   // 软启动（之前扫 0xE9 没反应，是参数不对）
0x30 0x04;   // PLL
0x41 0x00;
0xE0 0x02;   // 温度
0xE6 0x19;
```

### 刷新

```c
wait_cycle() = 先等 BUSY 拉低（进入忙），再等拉高（释放）
refresh(power_on, power_off) = [0x04 PON] -> 0x12 0x00 -> [0x02 POF]
```

初始化那几条寄存器之后**只等空闲**（不要求先进忙）—— 软启动不一定触发忙。

### 8bpp 索引 → 两个 3bit 平面

```c
high = ((index0 >> 3) << 4) | (index1 >> 3);   // 平面 0
low  = ((index0 & 7)  << 4) | (index1 & 7);    // 平面 1
```
每平面 4bpp、360 字节/行 × 480 行 = 172800 字节。

### ColorQual 3 相

```
wave(qual_phase1) + 写平面0 + refresh(PON, 不POF)
wave(qual_phase2) +          refresh(不PON, 不POF)   ← 复用 RAM
wave(qual_phase3) + 写平面1 + refresh(不PON, POF)
```

## 对之前结论的修正

| 我们之前的结论 | 实情 |
|---|---|
| `0x20` 是活的 LUT 寄存器 | ✅ 对，但**必须 799 字节** |
| `LUT_EN` 是空位 | ❌ **错** —— 有用，但要 `0x00` 前导 + `0xA9` |
| 3 bit → 一次刷新最多 8 色 | ✅ 对 —— 所以人家用**两个 3bit 平面分两次刷** |
| 多遍刷新需要非饱和波形 | ✅ 对 —— **人家自己写了 9 张波形** |
| 读 OTP 才能拿到波形 | ❌ 不用 —— 波形可以自己写 |
| 波形可能与兴泰屏不匹配 | ✅ **基本匹配**，色板正常 |

## 观察到的现象

- **复位前 BUSY = 0**（悬空有内部上拉应该读 1）→ 面板在主动拉低 = 面板活着
- 复位后 BUSY 0 → 1（释放）
- 软启动与四条 init 寄存器**都不触发忙**，BUSY 全程为 1
- 三次彩色刷新：BUSY 进入忙耗时都是 0 ms（拉低极快），释放分别 5.6 / 6.4 / 0.12 s
