# 3.7″ E6 48 色色板说明（FrameFilm）

> 数据源：`FrameFilm/docs/film/film.md` §10.6.1 / §10.6.2（64 索引全表）
> 代码实现：`FrameFilm/tools/ForFilm/js/convert.js`（`CF_PALETTE_FAST` / `CF_PALETTE_QUAL`）

抠好的 CSV：`palette_qual.csv`（ColorQual，3 相）/ `palette_fast.csv`（ColorFast，2 相）

---

## 一、为什么颜色「不均匀」

因为 8bpp 索引不是线性的，而是 **`高 3bit × 8 + 低 3bit`** 的组合：

- **高 3bit** 在 ColorQual 的第一相里决定「落在哪个色系」（8 个）
- **低 3bit** 在第三相里决定「在这个色系里走多深」（8 档）

所以 64 格里：

- 8 个色系之间的**覆盖范围天差地别**（有的整族都在暗部，有的跨亮部）
- 有相当一部分索引是**占位/未使用**（表里标 `·`），硬填进去只会得到重复或脏色

**这也解释了刚才那张索引卡为什么看着是 64 格：我把 0~63 全填满了。**
真正该用的只有下面列出的候选集。

`index = 高3bit × 8 + 低3bit`。行 = 高 3bit（色系），列 = 低 3bit（档位）。

## 四、两张表怎么选

| | ColorQual（`0x02`） | ColorFast（`0x03`） |
|---|---|---|
| 相数 | 3 | 2 |
| 候选色 | 52 | 57 |
| 实测耗时（我们这块屏） | 5.6 + 6.4 + 0.12 s | 未测 |
| 黑白 | **无真黑**，白只有 1 个 | 有真黑，白 1 个 |
| 适合 | 照片、需要细腻过渡 | 需要对比度 / 更快 |

## 五、量化时要注意的

`convert.js` 的选色规则（照抄）：
- **D65 CIELAB 最近邻**，**明度权重 ×2**
  （注释原文：墨水屏上明度保真比色度更重要，灰阶梯度也更单调）
- 只在 `candidateIndexes` 里选，占位索引不参与

⚠️ `film.md` 的 `有效` 列和 `convert.js` 的候选集**不一致**：
文档标 55 / 46，代码数组数出来是 **57 / 52**。**以代码为准**。

⚠️ `film.md` 表里的 `HEX` 列有明显笔误（index 0~2 的 R/G/B 是白 `255,255,255`，
HEX 却写 `#000000`）。**用之前逐项核一遍。**
